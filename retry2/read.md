[더미 노드 연결 리스트 순회: 포인터 주소값 기반의 명확한 동작 원리]

1. 내가 헷갈렸던 지점 (과거의 착각 vs 기계적 진실)
- 포인트 A: 'pTmp != NULL'의 의미
  (착각) "노드의 데이터가 비어있지 않다"는 의미로 오해함. 유의미한 데이터가 없는 더미 노드(Dummy)는 이 조건에 걸러질 것이라 생각함.
  (진실) "pTmp 변수 안에 들어있는 '주소값'이 0(NULL)이 아니다"라는 단순한 값 비교임. 더미 노드 역시 메모리 공간을 할당받아 고유한 주소값(예: 0x100)을 가지므로 pTmp는 NULL이 아니며 조건은 참이 됨.

- 포인트 B: 포인터(pTmp)와 역참조(*pTmp)의 혼동
  (착각) 포인터 변수 자체를 데이터 덩어리와 동일시함.
  (진실) pTmp는 단순히 '주소값(숫자)'을 담는 변수임. 반면, *pTmp는 그 주소로 찾아가 꺼내온 '거대한 구조체 데이터 덩어리 전체'임. NULL은 주소값(0)이므로, 데이터 덩어리인 *pTmp와는 타입 자체가 달라 비교할 수 없음(컴파일 에러 발생).

- 포인트 C: 루프 조건식의 평가 시점
  (착각) 다음 주소가 없다는 예측(pNext == NULL)이 현재 노드의 출력 작업에 미치는 영향을 연결하지 못함.
  (진실) while문은 내부 코드를 실행하기 전 문턱에서 조건을 먼저 검사함. 조건이 거짓이면 내부 코드는 단 한 줄도 실행되지 않고 즉시 강제 종료됨.

2. 개념 바로잡기 (메모리와 주소 관점)
- 노드(Node): 메모리에 할당된 실제 구조체 데이터 공간.
- pTmp (포인터): 현재 접근 중인 노드의 '시작 주소값'을 담고 있는 변수.
- pTmp->pNext: 현재 노드 구조체 안에 저장된 '다음 노드의 주소값'.
- pTmp = pTmp->pNext (이동 원리): 시선의 이동이 아니라, "현재 노드에 적힌 다음 주소값을 복사해 와서, 내 포인터 변수(pTmp)의 값을 지우고 그 위에 덮어써라(Overwrite)"라는 단순한 대입 연산.

3. 핵심 원리: 왜 (pTmp->pNext != NULL)은 마지막 노드를 누락시키는가?
- 조건의 의미: "현재 노드에 저장된 다음 주소값이 0(NULL)이 아닌가?"
- 마지막 노드 도달 시 벌어지는 일: 
  pTmp에는 마지막 노드의 주소값이 들어있음. 문턱에서 pTmp->pNext를 확인해 보니 마지막 노드이므로 다음 주소값은 NULL(0)임.
  따라서 진입 조건이 즉시 '거짓(False)'이 됨.
- 결과: pTmp는 정상적으로 마지막 노드의 주소를 가지고 있음에도 불구하고, 조건 검사에서 탈락하여 루프 내부(printf)로 진입하지 못함. 마지막 노드의 데이터가 출력되지 않고 누락됨.

4. 올바른 해답과 결론
- (pTmp != NULL) 조건을 사용해야 함.
- 의미: "현재 pTmp 변수에 들어있는 주소값이 0(NULL)이 아닌가?"
- 마지막 노드 도달 시 벌어지는 일:
  1. pTmp에 마지막 노드의 주소값이 들어있으므로 0이 아님 (조건 참).
  2. 루프에 진입하여 마지막 노드의 데이터를 정상적으로 출력함.
  3. pTmp = pTmp->pNext; 연산을 통해, 마지막 노드에 적혀있던 다음 주소값인 NULL(0)을 pTmp 변수에 덮어씀.
  4. 다음 턴 문턱에서 pTmp의 값이 0(NULL)임을 확인하고 루프를 안전하게 종료함.

* 최종 요약: 연결 리스트를 전체 순회할 때는 다음 노드의 주소값을 미리 내다보고 예측할 필요가 없다. 그저 포인터 변수(pTmp)가 가진 현재 주소값이 0(NULL)인지 아닌지만 직관적으로 비교하며, 다음 주소값을 계속 덮어써 나가면 마지막 데이터까지 누락 없이 처리할 수 있다.
